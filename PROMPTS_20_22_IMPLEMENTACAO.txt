ESTRUTURA DOS TESTES:

Cada teste segue padrão AAA (Arrange-Act-Assert):

  Arrange: Setup dos dados de teste (@BeforeEach)
  Act: Execução do teste (mockMvc.perform ou method call)
  Assert: Verificação dos resultados (expect ou assertions)

Exemplo:
  @Test
  void testLogin() {
    // ARRANGE
    when(authService.login(any())).thenReturn(response);
    
    // ACT
    mockMvc.perform(post("/api/v1/auth/login")...)
    
    // ASSERT
    .andExpect(status().isOk())
  }

COMO INTEGRAR HARDENING:

1. Rate Limiting:
   - RateLimitFilter já está configurada e intercepts todas as requests
   - Automático ao iniciar a aplicação

2. Audit Logging:
   - Injetar AuditLoggerService nos serviços
   - Chamar métodos apropriados em ações críticas
   
   Exemplo:
   @Autowired
   private AuditLoggerService auditLogger;
   
   public LoginResponse login(LoginRequest request) {
       try {
           // ... lógica de login
           auditLogger.logLogin(request.email(), true, "Credenciais válidas");
       } catch (Exception e) {
           auditLogger.logLogin(request.email(), false, e.getMessage());
       }
   }

3. Exception Handling:
   - Usar GlobalExceptionHandlerHardened ao invés do original
   - Validar semanticamente tipos de exceção
   - Sempre logar exceções

4. Constantes de Erro:
   - Usar ErrorMessages.* ao invés de strings hardcoded
   
   Antes:
   throw new BusinessException("A soma deve ser 100");
   
   Depois:
   throw new BusinessException(ErrorMessages.CRITERIO_WEIGHTS_INVALID_SUM);

5. Otimistic Locking:
   - @Version Integer version já está em todas as entidades
   - Exceção é tratada automaticamente pelo handler novo
